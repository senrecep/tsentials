---
title: "Migration guide: behaviour changes"
---

This guide lists every change that alters the runtime behaviour of an existing tsentials API. Read the 4.0.0 section when upgrading from 3.x, the 3.1.0 section when upgrading from 3.0.x, the 3.0.0 section when upgrading from 2.x, the 2.0.0 section when upgrading from 1.x and the 1.0.0 section when upgrading from 0.1.x. New APIs are listed in [CHANGELOG.md](https://github.com/senrecep/tsentials/blob/main/CHANGELOG.md).

## Behaviour changes in the next release (unreleased)

* **enums:** case-insensitive matching in `parse` (and the ambiguity checks of `defineEnum`) now follows C# `OrdinalIgnoreCase`: each character is upper-cased on its own. A character whose upper case is longer is no longer expanded, so `'STRAßE'` no longer matches the wire name `'strasse'`. The Turkish dotless `ı` and the long `ſ` no longer match `I` and `S`. Final and medial sigma still match. Members whose names differ only in these characters, such as `'aß'` and `'ASS'`, are no longer rejected as ambiguous.

## Behaviour changes in 4.0.0

* **string:** the case converters split words on Unicode rules, as CSharpEssentials does. Any character that is not a letter, combining mark or digit now separates words and is dropped: `toSnakeCase('foo.bar')` gives `'foo_bar'` (it was `'foo.bar'`). A digit run is its own word: `toSnakeCase('hello123World')` gives `'hello_123_world'` (it was `'hello123world'`) and `toCamelCase('v2Api')` gives `'v2Api'` (it was `'v2api'`). Non-ASCII uppercase and titlecase letters start a word: `toKebabCase('überÄpfel')` gives `'über-äpfel'` (it was `'überäpfel'`), and `toSnakeCase('user用户Name')` gives `'user用户_name'`. Acronym splitting is unchanged (`'XMLParser'` gives `'xml_parser'`).
* **enums:** `defineEnum` throws a `TypeError` for a wire name or alias that cannot be read back: empty, containing whitespace or a comma, or starting with a digit, a sign (`-`, `+`) or a dot (such text is read as a number). This also applies to wire names derived from member names by the naming policy. It used to accept them (only an empty wire name threw), and such a name could not be parsed.
* **enums:** negative zero is rejected. `parse` fails for `-00`, `-000` and so on (as it already did for `-0`) instead of returning the member with value 0, and `parseNumber(-0)` fails with the value `-0` instead of returning that member. In data mode these values are not mapped to the fallback member.
* **these:** `These.flatMap` on a `Both` whose continuation returns a `Left` now returns that `Left`. It used to return `Both(originalLeft, continuationLeft)`, with the continuation's error in the value field. `Right` and `Both` continuations are unchanged: they give `Both(originalLeft, newValue)`.
* **http:** `problemDetailsToErrors`, and so a failed `fetchResult` / `RequestBuilder` response, now reads the `errorCodes` extension that CSharpEssentials.AspNetCore writes. A problem body with `errorCodes: ["User.NotFound"]` and no `errors` used to give one `Http.404` error; it now gives `User.NotFound` with the type of the status and `detail` as the description. A code that also has entries in `errors` keeps those entries, codes listed only in `errorCodes` are added, and the errors follow the `errorCodes` order. Code that matched on `Http.{status}` for such responses must match on the domain code or on the type.
* **http:** `idempotentRetryClassifier` now follows the CSharpEssentials `IdempotentRetry` table. GET, HEAD, PUT, DELETE and OPTIONS are safe and every other method is unsafe: TRACE, CONNECT or a custom method without a key is no longer retried (before, only POST and PATCH were treated as unsafe). A safe method is now retried on every 5xx, 500 and 502 included; a keyed unsafe method still retries only 408, 429, 503 and 504. A 409 `Idempotency.InFlight` is retried only when `hasIdempotencyKey` is `true`; before, a GET or PUT without a key retried it too.
* **http:** a 2xx `fetchResult` / `RequestBuilder` response with a JSON content type whose body cannot be parsed is now a `Validation` failure (code `SyntaxError`, still with `httpStatus` metadata) instead of `Unexpected`, as in CSharpEssentials 8.0. The default retry classifier treats it as not retryable.
* **http:** a JSON request body that `JSON.stringify` rejects (cyclic object, BigInt) is now a `Validation` failure (code `TypeError`) instead of `Unexpected`, for `fetchResult.post` / `put` / `patch` and `RequestBuilder`. An invalid header on such a JSON request is a `Validation` failure too. No request is sent.
* **http:** `RequestBuilder.json()` no longer serializes the value: it never throws, and `send()` serializes it once per call. A cyclic or BigInt value used to throw from `json()`. A value changed between `json()` and `send()` is now sent as it is at `send()` time.
* **idempotency:** the problem+json rejections of `withIdempotency` are now built with `toProblemResponse` and gain fields; status, headers, `title`, `detail` and `code` are unchanged. Every body now has `type` (the RFC 9110 section link of the status) and `errorCodes: [code]`, and the `Validation` codes (`Idempotency.KeyMissing`, `KeyInvalid`, `ScopeRequired`, `KeyReused`) also have `errors: [{ code, description }]`. A client that compares the whole body must allow the new fields.
* **resilience:** a `withFallback` / `withFallbackResult` fallback that throws (not the caller's abort) now gives an `Unexpected` error (code: the thrown value's name) instead of `Failure`, matching how `execute` converts a thrown action and CSharpEssentials 8.0.
* **json:** `isJson` returns `false` for circular data instead of throwing `RangeError`. `isJson` and `isJsonPrimitive` return `false` for `NaN`, `Infinity` and `-Infinity`, which JSON cannot represent; they used to return `true`.
* **predicate:** `Predicate.toRule(p, error)` now returns a real `Rule<A>` from `tsentials/rules`: `Result.ok()` when the predicate holds, otherwise `Result.failure(error)`. `error` must be an `AppError`. It used to return `undefined` or the raw `error`, which `RuleEngine` could not use.
* **eq:** `Eq.number.equals(NaN, NaN)` is now `true`, consistent with `Ord.number`. `0` and `-0` stay equal. It used to be `false` (`===`).
* **record:** `map`, `mapWithKey`, `filter`, `filterMap`, `remove`, `pick`, `omit` and `partition` keep an own `__proto__` key (e.g. from `JSON.parse`) as an own data property of the result. They used to drop it, and an object value under that key became the result's prototype.
* **mediator:** `cachingBehavior` no longer throws `Failed to deserialize cached value for key {key}` when a cached entry cannot be read (the serializer returns `undefined` or throws, for example on invalid JSON). It logs a `warning` (`Cached value for key {key} could not be deserialized; calling the handler`), runs the handler and overwrites the entry with the new result, as a miss would. A request used to fail until the entry expired. `Cache hit for key {key}` is now logged only after the entry deserializes.

## Behaviour changes in 3.1.0

* **errors:** `Err.equals` now compares nested metadata by value: a nested metadata `Map` (such as the `innerException` map from `Err.fromException`) and a nested error created by `Err` (such as a `cause` entry) are compared recursively, and cyclic metadata terminates. Two errors whose nested metadata was built separately with the same content are now equal; they used to differ because nested values were compared by reference. Other values (plain objects, arrays) are still compared with `Object.is`.
* **http:** `fetchResult` and `RequestBuilder` now cancel the response body when they do not read it (a non-JSON error response, 204/205, a non-JSON 2xx), so the connection is released instead of staying busy until the body is garbage collected. Code that reads `response.body` itself is unaffected: these paths never expose the `Response`.
* **entity:** the object from `createEntityBaseWithId` now keeps `domainEvents`, `createdAt`, `createdBy`, `updatedAt` and `updatedBy` live, so they reflect later `raise`, `clearDomainEvents`, `setCreatedInfo` and `setUpdatedInfo` calls. They used to keep the values they had when the object was created. `createEntityBaseWithId` and `EntityBaseWithId` are now also exported from `tsentials/entity`.
* **entity:** `raise` throws a `TypeError` when the event is `null` or `undefined`, and `setCreatedInfo` / `setUpdatedInfo` throw a `RangeError` when the date is not a valid `Date` (not a `Date`, or an invalid one such as `new Date('x')`). Nothing is stored in that case. They used to store the value.
* **mediator:** `validationBehavior` now calls an object validator as a method, and uses its `validateAsync(request, { signal })` when it has one, instead of calling a detached `validate`. A `Validator` subclass from `tsentials/validation` used to fail every request with `Validator.Exception` because it lost `this`; it now validates, honours its `order`, and receives the caller's signal. An object with both methods now runs `validateAsync`, not `validate`.
* **validation:** the messages of `isDefinedEnum`, `isOneOf` and `hasOnlyDefinedFlags` now cut the echoed value to 64 characters plus `…`, as the C# enum validators and `EnumDefinition.createError` do. A value of 64 characters or fewer is shown as before.
* **result:** when the callback of a sync `Result.tap`, `tapError`, `tapErrorFirst`, `tapIf`, `tapErrorIf`, `switch`, `switchFirst` or `switchLast` (and the `ResultChain` methods that call them) returns a promise that rejects, the unhandled rejection is now a `TypeError` that names the method and the async alternative, with the original error as `cause`. It used to be the original error with no hint of where it came from. The callback is still not awaited and a fulfilled promise is untouched; use `Result.tapAsync`, `Result.tapErrorAsync`, a `ResultAsync` chain or `await Result.match(...)` for async work.
* **result:** `ResultUnwrapError` now extends the new `DomainError`, and `Result.try`, `Result.tryAsync`, `Result.tryCatch` and `Result.tryCatchAsync` return the errors a thrown `DomainError` carries as-is, even when an `onError` mapper or fixed error is given. `Result.try(() => Result.unwrap(r))` used to fail with one `ResultUnwrapError` Failure error; it now fails with `r`'s errors. `ResultUnwrapError.errors` is now a frozen copy of the array it was given.
* **mediator:** `exceptionHandlingBehavior` returns the errors a thrown `DomainError` (including `ResultUnwrapError`) carries as-is instead of one `Err.fromException` Failure error.

## Behaviour changes in 3.0.0

* **idempotency:** `withIdempotency` now defaults `unscopedKeyBehavior` to `'reject'`: a request with an `Idempotency-Key` but no scope (no `scope` option, or a resolver returning `null`/`undefined`) gets 400 `Idempotency.ScopeRequired` in `enforce`; `observe` logs `Idempotency.Observe.WouldRejectScopeRequired` and runs the handler. It used to run without idempotency (`'skip'`). Pass a `scope` resolver, or `unscopedKeyBehavior: 'skip'` to restore the old behaviour.
* **idempotency:** a 2xx response that `withIdempotency` cannot store (body over `maxResponseBodyBytes`, a non-identity `Content-Encoding`, or `text/event-stream`) now stores a marker for `retentionMs`: a retry with the same key and request gets 409 `Idempotency.ResultUnavailable` (no `Retry-After`) and the handler does not run. It used to get 409 `Idempotency.InFlight` until the lease ended and then run the handler again. Use `idempotentRetryClassifier`, which never retries this code; a generic `withRetry` without it retries any 409 Conflict. Use a new key only if repeating the side effect is intended. `onDecision` reports such a key as `'result_unavailable'` (in `observe`: `Idempotency.Observe.WouldRejectResultUnavailable`), not as `'replay'`. **Rolling deploy:** an instance still on 2.0.x that reads a marker answers 500 `Idempotency.StoredResponseUnreadable` (the handler does not run), so deploy every instance before relying on the 409.
* **idempotency:** `InMemoryIdempotencyStore` and `RedisIdempotencyStore` now implement the optional `extend`, so the engine extends the lease while the handler runs (a timer every `leaseMs / 3`, unref'ed) and a slow handler keeps its key in flight past `leaseMs`. In `enforce` the handler receives a signal that also aborts with reason name `ReservationLost` when the lease is lost (`extend` returns `false`, or no `extend` succeeds before the lease deadline; a throwing `extend` is retried) or 15 minutes after the reservation: the mediator's `ctx.signal` is a new combined signal (no longer the caller's signal object). When the handler then throws that abort (the signal's reason, or an abort-like error when the handler received the signal), the call answers `Idempotency.ReservationLost` (Unexpected; HTTP 503 with `Retry-After`) instead, and the key is released so a retry runs again; any other error is rethrown as before, and a caller abort still rejects with the caller's reason. A failure returned after the loss by a handler that received the signal is released instead of stored. `withIdempotency` still passes the original `Request`; set the new `bindRequest` option to hand the handler a request bound to that signal. Stores without `extend` keep the old behaviour.
* **idempotency:** `IdempotencyErrorCode` gains `Idempotency.ResultUnavailable` and `Idempotency.ReservationLost`, and `IdempotencyDecision` gains `'result_unavailable'`. An exhaustive `switch` or `Record` over these types must handle the new members.

## Behaviour changes in 2.0.1

* **idempotency:** in `observe`, a call whose setup throws (invalid key, out-of-range request `leaseMs` / `retentionMs`, a throwing `settings`, `releaseFailures` or `signal` resolver) logs `Idempotency.Observe.ResolutionFailed` and runs without idempotency instead of failing. In `enforce`, a throwing `signal` resolver of `idempotent()` now rejects the returned promise instead of throwing synchronously; in `off` it is not called.

## Behaviour changes in 2.0.0

* **runtime:** the minimum Node.js version is 22 (`engines.node` is `>=22.0.0`). The library uses the global Web Crypto API (`crypto.subtle`, `crypto.randomUUID`).
* **http:** the first error of a failed `fetchResult` / `RequestBuilder` response carries metadata: `httpStatus` (always, also when a 2xx body cannot be parsed or its read times out), `retryAfterMs` (from a valid `Retry-After`), `idempotencyReplayed` (`Idempotency-Replayed: true`) and `problemCode` (a string `code` field of the body). Keys the problem body already gave the error win. Code, type and description are unchanged; a test that compares a whole failure with `toEqual` now also sees the metadata.
* **resilience:** `withRetry` and `retryIfFailed` wait at least the `retryAfterMs` metadata of a failure's first error before the next retry, capped by the new `maxRetryAfterMs` option (default 30 000 ms). A `fetchResult` failure with `Retry-After` therefore waits longer than the backoff when the server asks it to. An `Idempotency.InFlight` failure carries `retryAfterMs` (the `retryAfterMs` setting, default 1 000), so `withRetry` waits at least that long before retrying it (still capped by `maxRetryAfterMs`).

## Behaviour changes in 1.0.0

* **results:** `Result.recover(r, match, fn)` now scans ALL errors for a match, not only the first. Use the new `Result.recoverFirst` for the old first-error behaviour.
* **results:** `Result.ensure` evaluates an error factory lazily, only when the predicate fails.
* **results:** `ResultChain` async methods (e.g. `bindIfAsync`, `compensateFirstAsync`) now return `ResultAsync<T>` instead of a bare `Promise<Result<T>>` (`alwaysAsync` still returns the callback's `Promise`), so the fluent pipeline continues without an intermediate `await`.
* **results:** `resultToMaybe` turns a `null`/`undefined` success value into `None`, so a void success (`Result.ok()`) now gives `None` instead of `Some(undefined)` (see the Maybe null normalisation below).
* **rules:** `RuleEngine.and` / `andAsync` now stop at the first failing rule and return only its errors; later rules are not evaluated. The previous collect-all behaviour is available as the new `RuleEngine.andAll` / `andAllAsync`.
* **rules:** every combinator built from an empty rule list (`and`, `andAll`, `or`, `linear`, `linearTyped`, `andTyped`, `orTyped` and all async variants) evaluates to the Validation failure `EMPTY_RULE_ARRAY` ("The rule array is empty."). Previously `and()` / `linear()` returned ok, `or()` threw, and `linearTyped()` returned the Unexpected failure `RuleEngine.Empty`.
* **rules:** `RuleEngine.andTyped` / `andTypedAsync` still collect all errors, but on success they now return the FIRST rule's value (previously the last).
* **rules:** `RuleEngine.evaluate` never throws. A rule that throws becomes the failure `Rule.EvaluationFailed`, as with `evaluateAsync`.
* **rules:** combinators (`and`, `andAll`, `linear`, `or`, `if` and the async variants) guard each node, so a throwing node yields `Rule.EvaluationFailed` instead of throwing out of (or rejecting) the whole evaluation. A caller abort still rejects with `signal.reason`.
* **rules:** a throwing rule always produces the code `Rule.EvaluationFailed` (type `Unexpected`, thrown message as description), whatever combinator it sits in, because rules and combinators are plain functions and the node type of a throwing child is not known.
* **maybe:** a `Some` never holds `null` or `undefined`. `Maybe.some(null)` / `Maybe.some(undefined)` return `None`, and `map`, `mapIf`, `mapAsync`, `bind`, `bindIf` and `bindAsync` turn a `null`/`undefined` result into `None`. The `Some` branch is typed `value: NonNullable<T>`.
* **maybe:** `tryFirst` / `tryLast` / `tryFind` return `None` when the found element is `null`/`undefined` (the search does not continue past it). Previously they returned `Some(null)` / `Some(undefined)`.
* **maybe:** `tryFirst(arr, predicate)` and `tryLast(arr, predicate)` accept an optional predicate; `tryFind` also looks up a `Map` by key (`tryFind(map, key)`) and a plain object by own key (`tryFind(record, key)`); `choose(items, selector)` maps each item to a `Maybe` and keeps the `Some` values.
* **maybe:** `maybeToResult(maybe, error)` is now an alias of the new `Maybe.toResult(maybe, error)`; with the null normalisation, `maybeToResult(Maybe.some(null), e)` is the failure `e`.
* **maybe:** `Maybe.fromTry` no longer swallows abort errors; an abort propagates to the caller. Any other thrown value still becomes `None`.
* **errors:** `Err` factories called without a code use the bare type name as code: `Failure`, `Unexpected`, `Validation`, `Conflict`, `NotFound`, `Unauthorized`, `Forbidden` (previously `General.Failure`, `General.NotFound`, ...). Descriptions are unchanged.
* **errors:** `Err.fromException` now defaults to `ErrorType.Failure` (was `Unexpected`). Pass the type explicitly to keep the old value.
* **errors:** the `ErrorMetadata.fromException` key `exceptionStack` is renamed to `exceptionStackTrace`. When `error.cause` is an `Error`, it is captured as a nested `innerException` map.
* **errors:** `ErrorMetadata.combine(base, additional)` keeps the value from `base` on key collision (first wins); `additional` can only add keys. Previously the value from `additional` replaced it (last wins).
* **errors:** `Err.fromException` merges the exception details with the supplied metadata; on key collision the exception details win.
* **errors:** `AppError` errors created through `Err` expose a non-enumerable `toJSON()`; `JSON.stringify` serialises metadata maps as plain objects.
* **errors:** `Err.equals` now compares metadata as well. Absent metadata never equals present metadata, even if empty.
* **http:** status mapping changes. Newly `Validation`: 411/413/414/415/416/417. Newly `Unauthorized`: 407. Newly `Conflict`: 412. Newly `Unexpected`: 408 (>=500 already was). Any other unlisted status maps to `Failure`.
* **http:** `fetchResult` and `RequestBuilder` apply a 30 s default timeout (failure code `Http.Timeout`) and accept an `AbortSignal`. A caller abort rejects with `signal.reason`.
* **http:** `RequestBuilder` keeps relative URLs relative. Previously they were resolved against a placeholder `http://localhost` origin.
* **http:** a 2xx response with a JSON content type and an empty (or whitespace-only) body, or a literal `null` body, is now a NotFound failure (code `NotFound`, "Response body was empty or could not be deserialized.") instead of a `SyntaxError` failure / `null` success. 204 and 205 responses and non-JSON bodies stay void successes (`undefined`). Applies to `fetchResult.get` / `post` / `put` / `patch` / `send` and to every `RequestBuilder.send<T>()`, DELETE included.
* **http:** `fetchResult.delete` succeeds on any 2xx without requiring a body: an empty or `null` JSON body gives `success(undefined)`. A non-empty JSON body is still parsed and returned; malformed JSON is still a failure.
* **http:** `RequestBuilder.header()` (and the new `headers()`) now ADD a value: setting the same (case-insensitive) name twice sends both values (`first, second`) instead of replacing the first. `Content-Type` is single-valued and is still replaced. Headers reach `fetch` as a `[name, value][]` list instead of a record.
* **http:** an HTTP error response whose ProblemDetails body has an `errors` extension now yields one `AppError` per entry instead of a single status-mapped error. Entries without a valid `type` (dictionary entries, plain strings, list items without/with an unknown `type`) are `Validation`, because an untyped `errors` extension only carries validation errors.
* **http:** `RequestBuilder.body(raw)` after `.json(x)` removes the `Content-Type: application/json` header that `json()` added (previously the JSON type stayed on the raw body); a `Content-Type` set with `header()` after `json()` is kept.
* **clone:** `deepClone` is a self-contained recursive implementation and no longer delegates to the native `structuredClone`. Functions keep their reference, symbols become `undefined`, and `Error` subclasses keep their prototype and own properties. Views over one `ArrayBuffer` keep sharing a single cloned buffer. Type dispatch uses brand checks (`Array.isArray`, `ArrayBuffer.isView`, internal-slot getters), so an object spoofing `Symbol.toStringTag` (e.g. `'Map'`, `'Array'`) or built from `Object.create(Map.prototype)` is cloned as a plain object, and built-ins from another realm are still recognised.

## New subpath-only modules and additions

* **modules:** `tsentials/validation`, `tsentials/resilience`, `tsentials/pagination`, `tsentials/enums` and `tsentials/mediator` are available only through their subpaths; the root entry does not re-export them.
* **resilience:** `maxAttempts` counts RETRIES, so the action runs at most `maxAttempts + 1` times.
* **results:** `Result.mapEachError` maps every error one by one; `Result.mapError` still transforms the whole error array.
* **results:** `traverseAsync` accepts `{ concurrency, signal }`; it stays sequential by default, results keep item order, and a caller abort rejects with `signal.reason`.
* **rules:** `RuleEngine.if` / `ifAsync` accept a plain `boolean` as condition in addition to a rule. `false` takes the `onFalse` branch, or is ok when there is no `onFalse`.
* **maybe:** `Maybe.format(m)` formats as `Some(value)` / `None`, and a nested Maybe recursively (`Some(Some(1))`, `Some(None)`). It is deliberately not called `toString`: an own `toString` on the `Maybe` namespace would break `String(Maybe)` and `` `${Maybe}` ``.
* **enums:** `defineEnum` throws a `TypeError` for invalid member sets: two members with the same wire name, an alias equal to another member's wire name, member name or alias (all compared ignoring case), or more than one `fallback` member.
* **mediator:** `lockBehavior` catches an error thrown by the lock handle's `release()` and logs it as a warning through the optional `LockBehaviorOptions.logger`; the handler's result or error is never masked, even when that logger throws. `loggingBehavior` serialises request/response payloads defensively (`bigint` values become strings; circular or otherwise unserialisable payloads are written as `String(value)` or a placeholder), and a throwing logger never fails the request.
* **resilience:** `retryIfFailed`: when the `shouldRetry` predicate throws after the caller's signal was aborted, the call rejects with `signal.reason`; otherwise the thrown predicate error becomes an `Unexpected` failure `Result`, like any other thrown error. A retry with `delay: 0` still yields to the event loop between attempts, so a timeout or caller abort can interrupt a synchronously failing action.
* **pagination:** keyset cursor `date` values are parsed strictly: out-of-range components (`2024-02-30`, `T24:00`, `+25:00`) are rejected, never rolled over, and a value without an offset (date-only or date-time) is read as UTC. Expanded years (`+010000-01-01T00:00:00.000Z`, `-000001-…`), as written by `toISOString()` outside 0000-9999, round-trip. A `CursorProtector` whose `tryUnprotect` throws yields `KeysetPagination.InvalidCursor`.
* **time:** the new `getAge(birth, provider)` reads today in the provider's new optional `timeZone`: `SystemDateTimeProvider` uses the host's local zone, `createFakeDateTimeProvider` uses UTC, and a custom provider without `timeZone` uses `utcNowDate()`.
